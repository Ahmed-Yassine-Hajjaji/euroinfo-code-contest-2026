## Modèle maître (set-partitioning + rôles) — `src/m7_cg.py`, `src/m7_cp.py`
- Rôles f_m, h_m, y_m, z_mt binaires ; colonnes λ_c = (créneau k=(m,t), sous-ensemble exact de datasets libres de
  type t, somme ∈ [lb, ub]). Dataset libre ≤ 1 colonne ; Σ_{c∈k} λ_c = f_m ; énergie ; données totales par type
  (h, y, colonnes) ≤ offre ; générateurs par type ; f+h+y ≤ 1 ; z ≤ h (z = h si besoin impossible).
- Décodage `realize()` : f par colonnes, générateurs puis h remplis avec copyrightés + libres restants (Pools de
  greedy.py, exact ≤ 300). Vérifié : le hint (rôles + paquets de best) se décode exactement en 272 299.
- Pricing : un DP de sac à dos (coût min à somme exacte S, 860 items × 115 k sommes, numpy, ~0,3 s) PAR TYPE,
  partagé par tous les créneaux du type ; backtracking par matrice booléenne (99 Mo).

## Ce qui s'est passé
1. **Génération de colonnes classique : échec de convergence** (`--time-cg`). Avec les seules colonnes de best, les
   duaux des datasets valent 0 (toute la valeur est portée par les lignes GUB et les créneaux sans colonne, dont le
   dual est arbitraire/non borné) → le pricing propose des colonnes « gratuites » qui n'améliorent rien. IPM sans
   crossover : idem. Avec 3 colonnes initiales par créneau : le LP maître progresse de +0,6 par itération
   (272 302 → 272 306 en 9 itérations, 80 k colonnes) : dégénérescence massive, inutilisable en 2 h.
2. **Pool de colonnes aléatoires + maître entier (price-and-branch heuristique)** : `--time-cg 0 --init-cols 20
   --extra 2 --rc-thr 100` : 20 tirages de prix (prix ∝ taille × U(0,7 ; 1,3) + bruit) → DP → 1 colonne de coût
   minimal par créneau et par tirage (+ 2 sommes lb+δ, δ ≤ 30) : 181 746 colonnes en 23 s
   (`runs/m7_pool_2_a.json.cols.json`). Puis en parallèle :
   - HiGHS MIP 6 threads, cœurs 0-5, 1 500 s, hint = best (`logs/m7_mip_a.log`, `logs/m7_highs_2.log`) ;
   - CP-SAT 6 workers, cœurs 6-11, 1 500 s, hint = best (`logs/m7_cp_a.log`, `logs/m7_cpsat_2.log`).
3. **Potentiel à U fixé** (`fin_fh.py 2 --keep-use 3600`, 5 s, optimal) : si l'on récupérait le gaspillage
   (+3 600 unités libres par type) sans changer l'ensemble des modèles, les bascules h→f donneraient
   272 299 → 272 379 (+80) ; avec +14 412 par type (irréaliste) 272 600. Le gain cible (+23) existe donc même à
   U fixé, à condition de ré-empaqueter TOUTES les données libres presque sans gaspillage.
4. **Résultat du maître entier sur le pool** : HiGHS (6 threads) prouve en 718 s que **272 299 est OPTIMAL dans ce
   pool** de 181 746 colonnes (borne = 272 299) ; LP maître = 272 302,2. CP-SAT (6 workers, 1 500 s) : aucune
   solution > 272 299, borne encore à 284 k. Conclusion : des colonnes « gaspillage minimal » tirées au hasard ne
   suffisent pas, il faut les colonnes d'une partition cohérente ; la CG classique ne les produit pas (duaux
   dégénérés : les créneaux d'un même modèle s'échangent leur valeur, et la valeur se loge dans les lignes GUB plutôt
   que dans les datasets → pricing par créneau inopérant, borne lagrangienne inutile). Un pricing par MODÈLE
   (somme des meilleures colonnes de tous ses créneaux) et une stabilisation duale seraient nécessaires : pas le temps.
5. **Piste suivante (m7_realize.py)** : rôles par MIP avec offre libre réduite de s unités/type, puis réalisation
   EXACTE par type avec un MIP d'affectation x[d, créneau] (≈ 200 k binaires par type, activation par créneau,
   modèle rétrogradé en h si un créneau échoue), puis h/y remplis en copyrighté. Test sur l'ensemble f de best
   (avec hint) : type 0 = 286/286 créneaux réalisés en 240 s.
6. **Résultats m7_realize** (rôles MIP 120 s, HiGHS d'affectation 300 s/type, hint = paquets de best + glouton) :
   - shrink 1 500/type : rôles 272 337 (borne 272 364) ; sans hint : 283/291 créneaux actifs sur les types 0 et 1
     (8 rétrogradations f→h par type ≈ −2 000) ; avec hint glouton : 287/291 déjà par le hint.
   - shrink 2 500/type : rôles 272 319 (borne 272 343) ; type 0 : hint 290/292, HiGHS n'active pas les 2 derniers
     en 300 s (6 428 unités libres inutilisées pour 2 créneaux de ~18 000 : il faudrait un gaspillage < 2 500/type,
     soit < 8,6 u./créneau, contre 12,5 dans best).
   → la réalisation exacte « par type » bute sur le même mur : le gaspillage minimal atteignable par un solveur en
     quelques minutes n'est pas inférieur à celui de best.
7. **Empaquetage CP-SAT** (`--pack cpsat`, `src/m7_pack_cp.py`, 6 workers, 300 s/type, hint paquets best + glouton) :
   shrink 3 600 (rôles 272 302) : types 0/1/2 → 289/290, 290/291, 302/303 actifs (hint 287, 288, 300) : CP-SAT
   améliore le hint de +2 par type mais il manque toujours 1 créneau par type (≈ −250 chacun).
   shrink 2 500 + HiGHS : 6 rétrogradations (−641) → **271 678** (valide, < best).
8. **Borne valide** (`src/m7_bound.py 2 --shrink 0`, MIP des rôles entier, 300 s) : **272 396** (LP : 272 399) ;
   meilleure valeur de rôles sans gaspillage 272 372. Avec un gaspillage ≥ 3 000/type (le niveau de best est
   3 600/type) la borne des rôles tombe à 272 332, et à 272 320 pour ≥ 3 600/type : **272 322 n'est atteignable
   qu'avec un gaspillage total < ~13 000 unités (contre 14 412 dans best) ET un meilleur choix de modèles** —
   ce que ni les solveurs exacts (HiGHS, CP-SAT) ni le LNS n'ont su produire.
9. shrink 3 000 + CP-SAT 240 s/type : rôles 272 304 → 4 rétrogradations (−228) → **272 076**.
   shrink 3 600 + CP-SAT 300 s/type : rôles 272 302 → 4 rétrogradations (−164) → **272 138** (meilleure réalisation m7).
   Boucle itérative (`--iters`, modèles non réalisables interdits en f, paquets précédents en hint), test 10 s/type :
   271 909 → 271 841 (l'interdiction déplace les échecs sur d'autres modèles).
